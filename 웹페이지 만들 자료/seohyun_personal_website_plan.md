## 1. 프로젝트 개요

### 1.1 구축 목적

한림대학교 식품영양학과 학생의 전공 학습, 프로젝트, 역량, 활동 및 성장
과정을 체계적으로 정리하는 개인 포트폴리오 웹사이트를 구축한다.

단순한 개인 소개 페이지가 아니라 교수 및 전공 관계자, 대외활동·인턴십
담당자가 방문했을 때 전공 관심 분야와 실제 수행 경험, 문제 해결 및 분석
역량을 확인할 수 있는 개인 브랜딩 공간을 목표로 한다.

### 1.2 핵심 목표

1.  개인의 전공 배경과 관심 분야를 명확하게 전달한다.
2.  전공 과제뿐 아니라 기획·연구, 데이터 분석, 콘텐츠 제작 경험을
    포트폴리오로 정리한다.
3.  프로젝트별 본인 역할과 기여도, 결과 및 배운 점을 구체적으로
    보여준다.
4.  자격증과 활동 이력을 상태 및 연도별로 관리한다.
5.  한국어와 영어를 모두 제공해 다양한 방문자가 내용을 이해할 수 있도록
    한다.
6.  서버 운영 부담을 줄이고, 추후 콘텐츠를 쉽게 추가할 수 있는 구조를
    채택한다.

### 1.3 타깃 방문자

-   **교수 및 전공 관계자:** 전공 학습 내용, 과제, 연구·기획 경험 확인
-   **대외활동 및 인턴십 담당자:** 지원자의 관심 분야, 실무 관련 역량,
    활동 이력 확인
-   **기타 방문자:** 개인 소개와 프로젝트 경험 확인

## 3. 사이트맵 및 정보 구조

### 3.1 전체 메뉴

1.  **Home** --- 대표 소개 및 주요 역량 요약
2.  **About Me** --- 학력, 전공 관심 분야, 학업 및 성장 방향
3.  **Skills** --- 전공·문서·협업·자격증·데이터·문제 해결 역량
4.  **Projects** --- 분야별 프로젝트 목록 및 상세 페이지
5.  **Activities** --- 자격증, 대외활동, 공모전, 봉사, 인턴십, 교내 활동
6.  **Contact** --- 이메일 보내기 기능

### 3.2 페이지 구성 원칙

-   각 메뉴는 독립된 페이지로 제작한다.
-   모든 페이지에 공통 헤더와 푸터를 제공한다.
-   현재 위치를 알 수 있도록 활성 메뉴 상태를 표시한다.
-   한국어와 영어 전환 시 현재 보고 있는 페이지를 유지한다.
-   프로젝트 상세페이지는 프로젝트마다 별도 주소를 갖도록 한다.
-   활동 상세정보는 활동 성격에 따라 상세 페이지 또는 동일한 상세
    템플릿을 재사용한다.

### 3.3 권장 URL 구조

``` text
/
├── index.html
├── about.html
├── skills.html
├── projects.html
├── activities.html
├── contact.html
├── project-detail.html?id=project-id
└── activity-detail.html?id=activity-id
```

GitHub Pages는 정적 사이트이므로 별도 서버 없이 페이지를 제공한다.
상세페이지는 공통 템플릿에 JSON 데이터의 식별자를 전달해 내용을 표시하는
방식으로 구현할 수 있다.

## 4.3 Skills

### 목적

전공 및 학업 과정에서 쌓은 역량을 분야별로 정리하고, 자격증·시험 준비
현황을 투명하게 표시한다.

### 확정된 역량 항목

1.  전공 지식
2.  문서·발표자료 제작
3.  협업·팀 프로젝트
4.  자격증 및 시험 준비
5.  데이터 분석·통계
6.  문제 해결·자료 조사

각 역량은 다음 요소를 포함한다.

-   역량명
-   간단한 설명
-   관련 경험 또는 프로젝트
-   관련 도구 및 학습 내용(확인된 경우)

### 자격증 분류

  분류               자격증·시험 후보
  ------------------ ------------------------------------
  전공 관련          영양사, 식품안전기사, 식품산업기사
  데이터·사무 관련   ADsP, 컴퓨터활용능력 2급

### 상태 표시

-   취득 완료
-   준비 중
-   응시 예정

**중요:** 현재 후보 목록은 과거 대화에서 언급된 시험과 자격증을 정리한
것이다. 실제 취득 여부와 최신 준비 상태는 공개 전에 반드시 확인한다.
확인 전에는 상태를 임의로 확정하지 않는다.

### 표현 방식

-   자격증별 상태 배지
-   분야별 분류
-   필요 시 취득 연도 또는 응시 연도 표시
-   연도별 정렬 또는 필터 기능과 연계

### 프로젝트 분류

1.  **식품·영양**
2.  **기획·연구**
3.  **데이터·분석**
4.  **디자인·콘텐츠**

### 목록 화면

-   프로젝트 검색
-   분야별 필터
-   프로젝트 제목 및 짧은 설명

8.  프로젝트를 통해 배운 점

### 프로젝트 후보 관리 원칙

-   동일한 프로젝트의 중복 파일은 하나의 프로젝트로 통합한다.
-   파일의 제목만으로 본인 역할을 추정하지 않는다.
-   팀 프로젝트는 본인 기여와 팀 전체 성과를 구분한다.
-   실제 결과물과 설명이 일치하는지 확인한다.
-   대표 프로젝트 선정은 다음 기준으로 판단한다.
    -   전공 관심 분야와의 연관성
    -   본인의 구체적인 기여도
    -   결과물의 완성도
    -   역량을 보여주는 정도
    -   외부 공개 가능 여부

### 추가 후보 자료

기존 대화에서 언급된 DASH-T 식단 밀키트 기획, 춘천 푸드핏 워크 프로젝트,
식품가공학 과제 등은 추가 검토 후보가 될 수 있다. 다만 현재 확인된 파일
자료로 간주하지 않으며, 실제 원본과 본인 기여를 확인한 뒤 등록한다.

지속적으로 기록한다.

### 포함 범위

-   자격증 취득 및 시험 준비
-   대외활동
-   공모전
-   봉사활동
-   인턴십 및 실무 경험
-   교내 활동 및 기타 경험

### 목록 및 정렬 방식

-   연도별로 묶어서 표시
-   각 연도 안에서는 최신 활동부터 표시
-   타임라인 형태로 구성
-   필요 시 활동 분야별 필터 제공

### 활동 상세 정보

1.  활동명
2.  활동 기간
3.  참여 목적
4.  본인 역할 및 담당 업무
5.  주요 활동 내용
6.  주요 성과
7.  활동을 통해 얻은 역량과 배운 점

활동 경험이 없는 분류는 빈 항목으로 노출하지 않는다. 새로운 활동이
생기면 같은 형식으로 추가할 수 있도록 설계한다.

## 4.6 Contact

### 목적

방문자가 이메일로 간편하게 연락할 수 있도록 한다.

### 구성

-   간단한 연락 안내 문구
-   이메일 보내기 버튼
-   이메일 주소는 화면에 직접 노출하지 않음
-   버튼 클릭 시 방문자의 기본 이메일 앱에서 메일 작성 창이 열리도록
    `mailto:` 링크 사용

### 설정 필요 항목

-   실제 수신 이메일 주소: **확인 필요**
-   이메일 제목 기본값: 예) `Portfolio Inquiry`
-   이메일 본문 기본값: 선택 사항

이메일 주소는 소스 코드 또는 설정 파일에 입력해야 한다. 주소를 화면에
표시하지 않더라도 `mailto:` 링크를 통해 주소가 완전히 비밀로 보호되는
것은 아니라는 점을 고려한다.

-   `SEOHYUN EOM` 텍스트와 조합

-   과도한 장식이나 식품 아이콘을 사용하지 않고 개인 브랜드 중심으로
    제작

### 5.5 헤더 및 푸터

### 5.6 애니메이션

-   스크롤 시 콘텐츠가 부드럽게 나타나는 효과

### 5.7 라이트·다크 모드

### 7.3 콘텐츠 데이터 관리

콘텐츠와 디자인 코드를 분리해 데이터 파일만 수정해도 화면이 갱신되도록
한다.

예시:

``` json
{
  "id": "sample-project",
  "category": "food-nutrition",
  "title": {
    "ko": "프로젝트 제목",
    "en": "Project Title"
  },
  "summary": {
    "ko": "프로젝트에 대한 간단한 소개",
    "en": "A short project summary"
  },
  "year": 2026,
  "role": {
    "ko": "본인 역할 확인 후 입력",
    "en": "To be completed"
  },
  "visibility": "public",
  "featured": false,
  "image": "",
  "references": []
}
```

실제 구현 시에는 JSON 데이터의 유효성을 검사하고, 비공개 자료가 공개
페이지에 로드되지 않도록 공개 상태를 필터링한다.

-   프로젝트 검색 및 분야별 필터

-   자격증 상태 표시

방향을 확정했으므로 이메일 복사 기능은 기본 구현 범위에서 제외한다.

## 8. 반응형 및 접근성

### 8.1 반응형 기준

PC와 모바일에서 동일한 디자인 체계를 유지하되 화면 폭에 맞춰 자동
조정한다.

-   넓은 화면: 콘텐츠 폭과 여백을 충분히 확보
-   태블릿: 카드 열 수와 간격 조정
-   모바일: 한 열 레이아웃, 메뉴 축소, 글자 크기 및 여백 조정
-   이미지: 화면 비율에 맞춰 크롭하되 주요 정보가 잘리지 않도록 설정
-   가로 스크롤이 발생하지 않도록 점검

### 8.2 접근성

-   충분한 텍스트와 배경 대비
-   키보드만으로 메뉴와 버튼 이용 가능
-   이미지에 대체 텍스트 제공
-   링크와 버튼의 목적을 명확히 표현
-   제목 태그를 계층에 맞게 사용
-   애니메이션 감소 설정 지원
-   언어별 페이지에 올바른 `lang` 속성 적용

## 9. SEO 및 검색 노출

구글 중심의 기본 검색엔진 최적화를 적용한다.

-   페이지별 고유한 제목(title)과 설명(meta description)
-   의미 있는 제목 구조(H1, H2 등)
-   검색엔진이 읽을 수 있는 시맨틱 HTML
-   이미지 대체 텍스트
-   `sitemap.xml`
-   검색엔진 등록을 위한 소유권 확인 및 사이트맵 제출 준비
-   모바일 친화적인 화면 구성
-   한국어·영어 페이지별 언어 정보 제공

검색 노출은 보장되지 않으며, 실제 색인 여부는 배포 후 검색엔진의 처리에
따라 달라질 수 있다.

방문자 통계나 행동 추적 기능은 초기 버전에 설치하지 않는다.

## 10. 개인정보·저작권·공개 정책

### 10.1 개인정보

공개하지 않을 정보:

-   학번
-   전화번호
-   개인 SNS 계정
-   불필요한 개인 식별 정보
-   다른 학생이나 팀원의 개인정보

이메일 주소는 화면에 직접 표시하지 않고 이메일 보내기 버튼으로 연결한다.

### 10.2 팀 프로젝트

-   팀 전체 성과와 본인의 실제 기여를 구분한다.
-   팀원 이름, 학번, 연락처 등은 삭제하거나 비식별 처리한다.
-   팀 과제 공개 가능 여부와 공동 작업물의 이용 허용 범위를 확인한다.
-   본인이 담당하지 않은 내용을 본인의 성과로 표현하지 않는다.

### 10.3 수업 자료 및 결과물

-   교수 강의안, 교재, 수업자료를 무단으로 공개하지 않는다.
-   제출용 과제 원본을 공개하기 전에 공개 허용 여부를 확인한다.
-   필요하면 일부 결과만 요약하거나 직접 제작한 이미지로 대체한다.
-   데이터 분석 프로젝트는 데이터 출처, 이용 권한, 개인정보 포함 여부를
    확인한다.
-   외부 이미지 및 참고 자료는 출처를 표시한다.

### 10.4 프로젝트 공개 등급

  공개 등급   표시 방식
  ----------- ------------------------------------------
  공개        프로젝트 설명 및 공개 가능한 결과물 표시
  일부 공개   요약·일부 이미지·비식별 결과만 표시
  비공개      웹사이트에 게시하지 않음

기본 공개 사이트는 검색엔진에 노출될 수 있으므로, 단순히 메뉴에서 숨기는
것은 비공개 보호 수단이 아니다. 비공개 자료는 웹사이트 파일이나 공개
저장소에 올리지 않는다.

## 15. 최종 요약

본 프로젝트는 한림대학교 식품영양학과 학생의 전공 관심 분야와
학업·프로젝트 경험, 다양한 역량을 보여주는 한국어·영어 이중 언어 개인
포트폴리오 웹사이트 구축을 목표로 한다.

디자인은 네이비와 화이트를 기반으로 한 세련된 미니멀 스타일을 적용하고,
`SE` 이니셜과 영문 이름을 조합한 개인 브랜드 요소를 사용한다. 6개 메뉴를
독립 페이지로 구성하며, 프로젝트는 분야별 검색과 필터를 제공하고 각
프로젝트별 상세페이지에서 목적, 과정, 본인 역할, 활용 역량, 결과 및 배운
점을 보여준다.

기술적으로는 HTML, CSS, JavaScript를 사용한 정적 웹사이트를 권장하며,
콘텐츠를 JSON 파일로 분리해 유지관리를 쉽게 한다. GitHub Pages 무료
호스팅을 통해 공개하고, 기본 SEO와 반응형 디자인을 적용한다.

개인정보, 팀 과제, 수업 자료, 데이터 및 저작권을 사전에 검토하고, 공개
가능한 정보만 게시한다. 아직 확인되지 않은 이메일 주소, 자격증 상태,
프로젝트별 본인 기여도는 실제 확인 후 입력한다.

**최종 산출물은 웹사이트 구축 계획서(MD 파일)이며, 실제 소스 코드 제작
및 배포는 이번 기획 범위에 포함하지 않는다.**
